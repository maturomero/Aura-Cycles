Aura Cycles - como correrlo desde Eclipse (2da entrega del TPO: API REST con JWT e IA en el panel)

Todo se hace desde Eclipse, sin terminal. Con Docker hay un atajo de un solo comando (README, arriba de todo),
pero el dia a dia es Eclipse.

Una sola vez
1. Traer la rama: clic derecho en el proyecto > Team > Pull. Despues F5 y Maven > Update Project.
2. Crear la base con Flyway: clic derecho en el proyecto > Run As > Maven build...
     Goals: flyway:migrate   Parametro: flyway.password = la clave de root de tu MySQL
   Crea repuestos_bici y aplica sql/migraciones en orden (V1 a V4, con los datos de prueba).
3. El servidor tiene que estar en standalone-full: vista Servers, doble clic en WildFly >
   Runtime Environment > Configuration file: standalone-full.xml.
4. Con el servidor levantado, correr configurar-entrega4.cli:
   Run > External Tools > External Tools Configurations... > Program > New
     Name:              configurar-entrega4
     Location:          la carpeta de WildFly + /bin/jboss-cli.sh   (en Windows: \bin\jboss-cli.bat)
     Working Directory: ${project_loc}
     Arguments:         --connect --file=configurar-entrega4.cli
   Seleccionar el proyecto en el Project Explorer y tocar Run. Tienen que salir varios
   {"outcome" => "success"} y ningun "failed". Se puede correr de nuevo sin romper nada.
   Hace tres cosas: el realm valida las claves bcrypt, los reintentos del broker (cada 10 s, 10 veces)
   y saca la pagina de bienvenida de WildFly (la raiz pasa a redirigir a la app).

Una sola vez para la 2da entrega (API REST e IA)
1. Traer la rama (Team > Pull), F5 y Maven > Update Project: baja la libreria del JWT.
2. La tabla pedido_idempotente (la usa el POST de la API) ya viene en la migracion V2.
3. Para ver la sugerencia de la IA en el panel: vista Servers > doble clic en WildFly > Open launch configuration >
   Arguments > VM arguments, agregar:
     -DIA_MODERACION=true -DIA_URL=http://localhost:8092 -DIA_API_KEY=simulado
   y levantar MockLLM.java igual que los otros dos simuladores (paso de abajo). Sin esto la app anda igual y el boton
   de la IA responde "IA sin respuesta".
4. La API no necesita tocar WildFly. Queda en https://localhost:8443/repuestos/api/v1 y el JWT se firma con una clave
   que la app genera al arrancar (o con -DJWT_SECRET=una-clave-de-32-caracteres-o-mas).

Una sola vez para el 3er checkpoint
1. Traer la rama (Team > Pull) y F5.
2. La columna resolucion_avisada (el aviso al cliente sale una sola vez) ya viene en la migracion V3.
3. Con Docker: si ya estaba levantado, docker compose down y despues docker compose up --build.

Una sola vez para la correccion de la 2da entrega (migraciones con Flyway)
1. Traer la rama (Team > Pull), F5 y Maven > Update Project.
2. Ya no hay schema.sql: el esquema esta versionado en sql/migraciones (V1, V2, ...).
   Si tu base ya estaba armada, correr una vez flyway:migrate (paso 2 de arriba): la toma como V4 y no borra nada.
   Para empezar de cero: borrar la base en Workbench (DROP DATABASE repuestos_bici) y correr flyway:migrate.
3. Cualquier cambio nuevo en la base va en un archivo V5__descripcion.sql. Nunca editar una V ya aplicada.
4. El build ahora corre Checkstyle (checkstyle.xml): si algo no respeta el estilo, Maven lo dice con archivo y linea.

Cada vez que se trabaja
1. Levantar los sistemas externos simulados. En src/test/java > ar.edu.uade.repuestos.integracion,
   clic derecho > Run As > Java Application sobre:
     MockMercadoPago.java     (Mercado Pago, puerto 8089)
     MockProveedorSoap.java   (proveedor mayorista SOAP, puerto 8090)
     MockLLM.java             (modelo de IA simulado, puerto 8092)
   Cada uno queda en su consola (se paran con el cuadradito rojo).
2. Levantar WildFly y desplegar como siempre.
3. La tienda queda en https://localhost:8443/repuestos (http://localhost:8080 redirige).
   El certificado es autofirmado: la primera vez, "Avanzado" > "Continuar a localhost".
   Usuarios: ana@mail.com, carlos@mail.com, lucia@mail.com, javier@mail.com y mod@mail.com (moderador),
   todos con Clave1234.

Tests desde Eclipse
- Unitarios: clic derecho en src/test/java > Run As > JUnit Test (392, menos de un minuto; uno espera 5 s a proposito
  para probar el timeout de la IA).
- Las clases que terminan en IT (RepositoriosIT, MensajeriaIT) usan Testcontainers y necesitan Docker
  abierto. Sin Docker, Eclipse las saltea solas. Con Maven: clic derecho en el proyecto > Run As >
  Maven build... > Goals: verify (corre todo, mas cobertura JaCoCo).
- Mutacion: Run As > Maven build... > Goals: test-compile org.pitest:pitest-maven:mutationCoverage
  El reporte queda en target/pit-reports/index.html.
- Los E2E, ZAP y la carga con k6 corren contra docker compose (README, seccion 9). En el CI corren solos.

La API REST (2da entrega)
- Con la app levantada, desde una terminal en la carpeta del proyecto (en Windows, Git Bash):  ./demo/api.sh
  Recorre login con JWT, 401 y 403, Idempotency-Key, ETag y el 409 del State, y dice si cada paso dio el codigo esperado.
- El contrato esta en docs/api/openapi.yaml y las decisiones en docs/adr/ADR-008-api-rest-jwt.md.
- Como moderador, en Resenas pendientes: "Pedir sugerencia a la IA". Con http://localhost:8092/__modo en "lento" o
  "error" sale "IA sin respuesta" y se modera como siempre.

Mercado Pago real (credenciales de prueba)
1. En mercadopago.com.ar/developers > Tus integraciones, crear una aplicacion Checkout Pro. La cuenta vendedora de
   prueba se crea sola. Copiar el Access Token de "Credenciales de prueba" (empieza con APP_USR-).
2. En "Cuentas de prueba" crear una cuenta compradora de Argentina.
3. Vista Servers > doble clic en WildFly > Open launch configuration > Arguments > VM arguments, agregar:
     -DMP_ACCESS_TOKEN=APP_USR-... -DAURA_URL=https://IP_DE_TU_MAQUINA:8443/repuestos
   Reiniciar. En la consola sale "[MP] usando Mercado Pago real". Para volver al simulado, borrarlas.
- El token queda en el workspace de Eclipse, no en el repo. En la pestaña Common no tildar "Shared file".
- Mercado Pago no acepta localhost como URL de vuelta: por eso la IP de la maquina (ipconfig / ifconfig)
  y la tienda se abre con esa misma direccion. Si quedo en localhost, la consola lo avisa al arrancar.
- Pagar desde una ventana de incognito, logueado en Mercado Pago con la cuenta compradora de prueba, con la tarjeta
  5031 7557 3453 0604, codigo 123, vencimiento 11/30, DNI 12345678 (titular APRO aprueba, OTHE rechaza).
- Con docker es lo mismo pero en un archivo .env: copiar .env.example y completar las tres lineas de Mercado Pago.

Si alguien arma WildFly de cero
Copiar db.local.properties.example como db.local.properties y poner la clave de su MySQL (no se sube,
esta en el .gitignore). Otra External Tool igual a la del paso 4, con Arguments:
  --connect --file=configurar-standalone-full.cli --properties=db.local.properties --resolve-parameter-values
Ese ya incluye lo de configurar-entrega4.cli salvo los reintentos del broker: correr los dos.

Que cambio para la Clase 15 (testing)
- Tests: unitarios con Mockito, integracion con Testcontainers (MySQL y Artemis de verdad), E2E con
  Playwright, mutacion con PIT, ZAP, k6 y SpotBugs con FindSecBugs. Todo corre en GitHub Actions.
- Seguridad: CSP sin 'unsafe-inline' (los style="..." pasaron a clases de app.css), headers tambien en
  el login que muestra el contenedor y en las paginas de error, emails solo ASCII (registro y perfil),
  vista vencida vuelve a la pagina con un aviso en vez de un 500.
- Las fuentes IBM Plex ahora las sirve la app (la CSP bloqueaba Google Fonts y no cargaban).
- El detalle de cada defecto encontrado esta en el registro de defectos del documento de QA.
